# threads-cardnews

## 0. 작업 폴더 구조 (처음 한 번 정하고 이 표를 자기 경로로 고친다)
| 경로 | 내용 |
|---|---|
| `<작업 폴더>/올릴것/<주제>_<YYYYMMDD>/` | 게시 세트: 01~NN png/mp4, 피그마용, 본문.txt, 첫댓글.txt |
| `<작업 폴더>/카드뉴스_템플릿.md` | 레이아웃·구성 기준 |
| `<작업 폴더>/회차표_*.md` | 게시 예정 주제 순서 |
| `<작업 폴더>/게시기록.md` | 회차별 폴더와 "게시 완료/미확인" |
| `<작업 폴더>/_생성스크립트/` | 공용 틀과 회차별 캡처(cap_*.py), 조립(build_*.py) 스크립트 |

## 1. 상태 파악 ("말해줘"·"열어줘")
1. 게시기록 마지막 항목과 `올릴것` 폴더 목록(날짜순)을 대조한다.
2. 게시 미확인 세트가 있으면 지난 세트가 올라갔는지 사용자에게 먼저 한 번만 묻는다.
3. 올릴 세트가 있으면 4번 체크를 돌린 뒤 이름·장수·본문 첫 줄을 알려 준다.
4. 올릴 세트가 없으면 회차표의 다음 주제를 알려 준다. 회차표가 다 떨어졌으면 research-first 스킬로 주제 후보 3개를 근거와 함께 내고 고르게 한다.

## 2. 제작 ("만들어줘")
1. 주제 근거 조사: research-first 스킬로 공식 문서(NN/g, 애플 HIG, 플랫폼 도움말 등) 확보, `자료조사_<주제>_<날짜>.md`에 저장.
2. 최근 세트의 cap_*.py / build_*.py 중 형식이 가장 가까운 것을 복사해 문구·화면만 바꾼다. 처음부터 새로 짜지 않는다.
3. 예시 화면은 직접 만든 가상 가게 화면이나 자사 서비스로 만든 사이트. 남의 실제 가게 사이트·사람 얼굴 금지.
4. 결과는 `올릴것/<주제>_<YYYYMMDD 게시일>/`. 작업 파일은 `_시안_<주제>/`.

## 3. 본문·첫 댓글
- 본문을 다 쓴 뒤 가장 센 문장을 맨 위로. 첫 줄은 6유형(질문·숫자·고백·반전·경고·저장) 중 하나, 직전 회차와 다른 유형.
- 반말 질문, "~에요"·물결표·엠대시·명령형 금지. 정답·링크는 첫댓글.txt.

## 4. 넘기기 전 체크 (기존 세트 추천할 때도 전부)
- `references/checklist.md` 전 항목
- mp4는 `ffmpeg -frames:v 1`로 첫 프레임을 뽑아 제목·핵심 화면이 보이는지 확인(빈 판 금지)
- png를 직접 열어 피드 미리보기 잘림·겹침 확인
- slop-check 스킬로 본문.txt·첫댓글.txt 검사

## 5. 마무리
- 게시기록에 회차 한 줄 추가(폴더, 장 구성, 생성 스크립트, 근거 출처, "게시 여부 미확인").
- 보고: 폴더 경로, 장 구성 한 줄, 본문 첫 줄.
