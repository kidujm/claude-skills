# collab-mail

## 1. 상황 정리
- 받는 사람, 목적(제안·문의·요청·확인·사과), 꼭 들어갈 사실(금액·기한·링크·첨부)을 정리한다. 빠진 사실은 지어내지 말고 `[확인 필요: 항목]`으로 남긴다.
- 상대가 일정을 거듭 미룬 상황인지 확인한다. 그렇다면 단호 모드(3번).
- 사용자가 준 원고·문장이 있으면 워딩을 유지하고 말투만 바꾼다. 구성을 새로 짜거나 문장을 갈아엎지 않는다.

## 2. 관례 확인
research-first 스킬로 같은 목적의 직장인 협업 메일 예시 3건 이상을 찾아 구성(인사 > 소개 > 용건 > 요청 > 기한 > 맺음)과 표현을 참고한다. 같은 대화에서 같은 목적으로 이미 찾았으면 다시 찾지 않는다.

## 3. 말투
- 기본: 쿠션어로 둥글게. 요청은 "번거로우시겠지만 ~해 주실 수 있을까요?", "가능하시다면 ~해 주시면 감사하겠습니다", 주의사항은 "~점 참고 부탁드립니다". "~해 주세요", "~해야 합니다", "답변드립니다" 같은 통보형 금지.
- 우리 쪽 안내가 틀렸거나 부족했으면 "확인해 보니 ~더라고요" + 짧은 사과 한 줄.
- 단호 모드: 감사 표현은 맺음 한 번만, 기한을 날짜로 박고 "~까지 회신 부탁드립니다".
- 감정 표현 빼고 사실 중심.
- 순우리말 대신 한자어·외래어 우선(slop-check 3-1).
- 회사는 팀 이름으로 지칭하고 개인 이름으로 회사를 대신하지 않는다.

## 4. 여러 명이면
- 대상 목록(시트 등)의 전원을 쓴다. 일부만 쓰지 않는다.
- 공통 본문 + 사람별 맞춤 한두 문장(채널 이름, 최근 콘텐츠 주제 등 실제 확인한 것만).
- 한 파일에 사람별 구획으로 묶는다: 받는 사람 / 제목 / 본문.

## 5. 검사와 저장
- slop-check 스킬로 검사.
- 저장: 작업 폴더 아래 `<YYYYMMDD>_<주제>_메일/메일초안.md`. 발송은 하지 않는다(외부 발송은 사용자가 직접).
- 보고: 제목 줄과 본문 첫 두 문장, `[확인 필요]` 항목 목록, 참고한 예시 링크.
