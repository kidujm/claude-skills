# research-first

## 1. 질문 정하기
- 무엇을 근거로 정해야 하는지 한 줄로 적는다(예: "인플루언서 가격 문의 메일의 통상 구성과 말투").
- 내 지식으로 이미 아는 답이 있어도 검색부터 한다. 관례·규격·가격·서비스 기능은 바뀐다.

## 2. 수집
- WebSearch로 국문·영문 각각 검색, 3~5건 확보. 특정 사이트·플랫폼 글을 읽어야 하면 insane-search 스킬.
- 출처 우선순위: 공식 문서·플랫폼 도움말 > 실제 서비스 화면·공개 사례 > 업계 매체 > 업체 가이드·칼럼. 개인 블로그는 쓰지 않는다.
- 디자인·영상 레퍼런스는 대화 속 캡처 한 장을 따라 하지 않는다. 여러 개를 모아 공통 패턴을 뽑는다. 영상은 yt-dlp로 받아 첫 3초·컷 길이를 직접 본다.
- 사례 링크는 직접 열어서 열리는지 확인한다. 안 열리면 안 열린다고 적는다.

## 3. 정리
- 공통 패턴 3~5개를 뽑고, 각 패턴 옆에 근거 출처를 붙인다.
- 출처마다 신뢰 수준을 밝힌다(공식 / 사례 / 칼럼 수준).
- 사실 주장은 출처 원문과 한 번 더 대조한다(2회 검증). 확인 안 되면 "확인 안 됨"으로 둔다. 지어내지 않는다.

## 4. 적용
- 패턴을 산출물에 반영한다. 사용자가 준 원고가 있으면 워딩은 유지하고 형식·말투만 반영한다.
- 산출물 맨 아래나 보고에 "참고한 자료" 목록(제목 + 링크)을 붙인다. 남에게 보낼 산출물(메일 본문 등)에는 넣지 않고 대화 보고에만 붙인다.

## 5. 보고
- 몇 건을 봤고, 어떤 패턴을 반영했고, 무엇이 달라졌는지 2~4줄.
- 의사결정 제안("~해야 한다")은 하지 않는다. 사례와 현재 사실만.
